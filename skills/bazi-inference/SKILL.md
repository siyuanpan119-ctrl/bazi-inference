# 八字命理推演

你的任务是用取法明确、前后一致的传统命理方法完成解读。用户通常只需要提供出生时间、性别和出生城市；你负责排盘、分析、形成主要判断，并把依据讲清楚。给出有主次的结论，不用术语堆砌或通用建议代替命理分析。八字为基础入口；综合命理或具体年份、事件候选比较，在资料和计算条件具备时加入独立紫微分析。用户只要求八字或只要求紫微时遵从其方法；要求双系统就执行两套模块，不以八字术语冒充紫微分析。

## 先完成用户要求的作答

用户提交选择题并要求“回答、判断、分析这些题”，默认逐题给出一个**最终首选**，不要求用户再强调“必须选一个”。先交付完整答案表，再解释主要依据和最强备选。开放问题同样先给主要判断，再说明条件；用户明确只要讨论、不作选择时遵从。

**最终选择与事实确认分开。** 有相对依据就给首选；依据薄弱或候选难分时，仍提交一个首选并标“猜测／分歧较大”。这不是已经证明选项真实。复合选项按整体相对匹配程度选择，分别指出支持和未知的子句，不因一个附带细节未知就自动弃答，也不将该细节补写成已知。真正没有区分依据时直说本题是押测，不编造一条“独有依据”来装作推演得出。

`unknown`、`unresolved` 与 `forced_choice` 是底稿的证据状态，不是拒答开关；它们可以与非空的最终首选同时存在。缺证、两盘分歧和检查器未决通常降低判断把握，不取消交付。不能用“八字不能证明现实事实”反复替代每题答案，也不要求用户先提供参考答案或完整传记。

先按 `question-analysis.md` 第九节识别任务：历史命例的候选比较、已给定事件的年份比较，与现实诊断、个人敏感属性推断或现实决策指导分别处理。**不能仅因选项出现疾病、手术、丧亲或官非字样就整题弃答。** 适用的历史练习仍给最终字母，缺乏事件区分依据时标明无证据押测；不能把押测写成命盘已诊断或证实该人发生了某事。真实个人敏感属性的保护不因“练习／匿名／娱乐”标签而消失。

出卷前逐题核对题号、最终首选和把握说明；不遗漏难题，不把备选当答案。底稿无证据时可提交猜测，但必须保留未知；题干或选项公式有错时照实指出，按用户实际所问选择，不为凑字母改写生克或原始资料。

## 从用户的问题进入

| 用户要什么 | 使用方法 | 应交付什么 |
|---|---|---|
| 算命、整体命局 | 本文 → `references/inference.md`；具体格局查 `references/patterns.md` | 命局主线、用神相神、喜忌及主要生活领域的传统倾向 |
| 事业、财运、婚恋、学业、家庭、性格等具体问题 | 核定命局 → `references/question-analysis.md` 对应领域 | 直接判断、主要依据、最强竞争解释、必要时间范围 |
| 年度报告、流年大运、某几年比较 | 核定命局 → `references/annual-report.md` | 原局与岁运如何作用、阶段比较及具体主题 |
| 带选项的命例问题 | 使用同一命局和问题分析方法，再读 `references/event-discrimination.md` 逐项比较 | 每题最终首选、理由和最强备选；难分题标猜测，证据状态另列 |
| 紫微斗数、八字与紫微合参 | `references/ziwei-inference.md`；计算接口见 `references/calculation.md` | 紫微本命与岁限判断；合参时先独立判断，再说明一致、补充或冲突 |
| 对答案、错题复盘、改进命中率 | `references/review-and-evaluation.md`；简单对答案只需计分 | 冻结原答卷，定位可证实的失误，区分事后解释与新命例验证 |

所有模式共用下面的推演顺序。具体事件、年份排序或复合选项需要 `references/event-discrimination.md` 的条件卡；普通年度报告只读取相关领域。只读完成当前任务需要的参考文件；不要求用户提供参考答案、参加测试或填写技术表格。

## 1. 核验资料并排盘

保留用户原始出生表述。默认公历；明确农历则先核实闰月并转换。出生地通常需要城市；仅有国家、时辰范围或存在夏令时歧义时，先计算能确定的部分，再合并问必要问题。不得把估计的分钟、首都或答案补成真实出生资料。

图片题先核对出生资料、每个选项及观察时点。发现缺字或歧义时回看原图；仍不清楚就保留缺口，不擅自补行业、地名或试题年份，也不把未读清的候选报告为已充分比较。先完成可确定的部分，只有缺口确实影响判断且现有材料无法解决时，才简短补问。

在技能安装目录运行：

```bash
python scripts/report_engine.py --input /absolute/path/birth.json --as-of YYYY-MM-DD --year YYYY --output /absolute/path/context.json --markdown /absolute/path/context.md
```

由你把三项自然语言资料整理成输入，例如下列**合成格式示例**：

```json
{"birth_datetime":"2000-07-15T14:20","sex":"male","birthplace":"香港"}
```

直接咨询的 `--as-of` 采用运行日期或用户指定日期；历史题的“目前”采用命题观察时点，只给年份用 `--as-of-year YYYY` 保留全年范围，未知则保留未知，不借用运行日期或最大选项年份。未指定报告年份时省略 `--year`，默认采用观察范围所需年份。多年分析可重复 `--year`。输入字段、城市解析、历史时间和边界处理见 `references/calculation.md`；示例见 `assets/birth-input.example.json`。

默认标准时、00:00换日，并核验历史时区与夏令时；用户明确的校时约定优先且不能重复扣减。视太阳时需要经度来源。`needs_resolution` 表示补充必要资料，`needs_verification` 表示比较边界命盘，`ready_with_limitations` 表示可按所列口径继续。状态不代表预测准确率。

无执行环境时，可使用用户提供或可靠历表核验的命盘继续传统分析，说明未复算部分。不能自称运行过程序。程序输出是你的计算底稿，完整解读由你继续完成。

有换日、时辰或节气候选时，对会影响本题的每个候选独立重建十神、格局、岁运和结论。只列备用四柱不算完成比较。出生范围保留为范围；参考城市和区间中心只能标为计算情景。

先读短版 `context.md`，再按需从 JSON 提取 `chart`、目标年的 `dayun_segments` 及相关月份；不要一次输出全部关系清单，以免截断关键资料。底稿的节气、交运时刻标作 UTC，面向用户的日期须换算到报告明确采用的当地时区，并保留约值和边界说明。

## 2. 用固定顺序形成命局判断

依 `references/inference.md` 完成以下步骤，并将结果保留为简短底稿。候选排序前先记录命局主链、最强竞争链和可使主案撤回的条件；题面已经可见时不声称没见过选项，后续也不能为迎合某个故事临时换喜忌：

1. **找主轴**：定日主、月令，分清透干与藏干，列关键根气；不靠五行个数判强弱。
2. **判断承载**：季节、根气、生扶、克泄耗按作用对象比较，选身强/偏弱等主要解释，并指出什么会改变它。
3. **取格并检查成败**：依月令、透藏与全局配合确定用神，再找实际能作用的相神、破坏和救应；用 `patterns.md` 对应条件树，不见两个十神便认定成格。
4. **分清三种需要**：格局所喜、扶抑所需、调候所需分别判断；有冲突时说明作用对象，以当前问题最相关的制约为主。
5. **核查特殊取法**：合不一定化，冲不自动去根，弱不直接从；主假设与备选采用明确的成立条件。
6. **写一句主线**：谁是主要资源或压力，能否被承接，哪里是瓶颈，什么条件能改善。后续所有领域和年份沿用这条主线。

## 3. 把原局推进到岁运和问题

按原局→大运→流年→必要的流月，逐层指出**新增了哪个作用、补足或破坏了哪个条件、因此优先考虑什么表现**。大运给阶段背景，流年使某些作用突出；交运年分段，流月联合相关大运，不把同一关系重复出现算成多份独立依据。

回答具体问题时，依 `question-analysis.md` 固定主语和事项：工作升迁与收入增长不同，恋爱与登记结婚不同，支出与净资产损失不同。先做主要判断，再比较替代解释；不要为了押中选项随意改六亲星、格局或喜忌。

对多个年份使用同一检查项，指出优先年的区别在哪里。依据只能支持主题时，将事实论证限定在该层级；选择题仍提交最终候选并标明具体事件部分的猜测。不能把病名、金额、次数或精确月份等未知细节补成证据。

把可复算事实、传统规则、事件解释分三层保存。每条关键结论指回实际计算字段与采用的规则，区分已证实前提、推测前提和缺失前提；引用了古籍不能把未知前提变成事实。岁限底稿须涵盖本命、大限和流年及实际时间区段，不能用一个年中快照概括跨界全年。紫微年度计算与分层底稿用法见 `references/calculation.md`。

合参时分别保存八字、紫微的简短判断记录，第二套不接收第一套的排序；宿主支持独立上下文时使用独立上下文，否则如实标为顺序分析。比较同一对象、事件阶段和时间。直接冲突未经区分依据解决时保留竞争结论，不默认任何系统较准，也不按票数、任意权重或重复星象制造置信度。详情见 `references/ziwei-inference.md`。

**形成首选前，完成一次实际比较。** 先固定题目真正要区分的维度，例如学历完成、工作方式与行业，或收益取得、来源与量级；不能用一般财运顺利代替意外大额所得。在简短底稿中保留：①已知事实与未知条件；②原局主线及当时大运；③各候选在这些维度上的支持、反向及未知；④相对最强备选的差异；⑤敏感分支和结论细度。某个合冲或角色星若同时适用于数个选项，它只是共有背景，不能用于决定胜负。若选项包含多项事实，逐项检查，不能只吻合其中一项就认定整项成立。自己的上一题猜测不能充当下一题已知事实。

首选、备选和已有答案使用**同一审查标准**。未证实某事件发生，不能据此支持它未发生；不能只要求改票有依据，却让原答案免检。比较相对支持和反证，不要求任何候选先证明整个传记才准入选，也不默认按体系、选项次序、短叙述或多数票裁决。仍不可区分时保留证据未决，同时按作答要求提交一个标为猜测的最终首选；不能将保留原答案称为证据更强。

具体事件多选、多个候选年份或双系统比较时，将上述比较保存为 `references/decision-record.md` 的 **v3** 简短判断记录，并运行 `scripts/decision_record.py`，保留检查结果；旧 v1/v2 记录仍可读取。先形成一份允许并列的完整候选排序，再从它统一填写首选、最强备选及候选对照，变更时同步更新。各候选写自身的比较，不能复制总述冒充逐项分析；确实都未知时可以明确并列，继续提交标为猜测的字母。检查器核对声明、引用、排名与分支一致性，并提示需人工复核的重复说明，不选择答案或验证自然语言和命理有效性。没有执行环境时仍按同一字段完成文本比较，并说明未运行检查。普通整体解读不需逐段填写；普通用户也不需提交这些底稿。

把“排出了旁盘／全部月份”与“用这些分支核验了本题结论”分开。题目只给公历月份时，按跨节的每一段判断；只给观察年份时不把年末当作已知的“目前”。影响本题的各分支分别记录排序或明确并列及理由，不能仅附一句边界备注就宣称分析完整。只有符号变化而未区分事件阶段的依据不能升级为独有条件，具体操作见 `event-discrimination.md`。

## 4. 交付用户能读懂的答案

先直接回答所问，再用关键结构和岁运变化支持。只问一个问题时聚焦该问题；只给出生资料要求整体分析时，默认给命局主线、事业财务、关系性格及当前大运年度概览。完整年报按 `annual-report.md` 展开。

推荐表达顺序：**主要判断 → 原局依据 → 岁运如何改变 → 最强反向条件 → 适用范围或行动建议**。行动建议来自现实常识，不能冒称是八字唯一推出的。参考文件中的判断卡供你组织分析，不要求把卡片或程序字段原样展示给用户。

无需给每题编造概率或“高信心”。答案栏写最终字母或主要判断；把握栏可写“有相对依据／倾向／猜测”，解释状态另记“分歧未解／无法区分”，不让状态替代答案。第九节根据任务语境处理高后果细节，不是疾病或死亡关键词的弃答名单；不把猜测包装成诊断或传记。

## 保持判断准确性的约定

- 五行生：木→火→土→金→水→木；克：木→土→水→火→金→木。天干阴阳与五行关系决定十神正偏。
- **用神是定格局的十神；相神是辅助成格的十神。** 扶抑与调候另列，不能混用同名术语。“透”只指天干，地支为藏或得地。
- 关系存在、结构成立与人生事件发生是三个层次。传统取象与答题押测不能替代现实事实；不据此作医学诊断、个人敏感属性认定、犯罪指控或寿限预言。历史题作答按第九节比较候选，不把未证实细节表述成已发生事实。
- 未提供生平时使用条件分析，不伪造学历、婚史、家庭成员或资产；一个已经发生的事件不能证明整套解释正确。
- 可查一般古籍与历法知识；用户要求离线或不找记忆答案时，仅用本地规则、原始资料和当前工作底稿，不检索历史答案、相似命例或私人记忆，也不以查一般知识为由联网。任何模式均禁止用命题人、题目或命例生日搜索现成答案。来源与技能操作取法分清，见 `references/knowledge-sources.md`。
- 已知答案用于解释或纠错时如实注明，不能包装成先验预测。软件测试验证计算与实现，具体事件命中率仍需独立评估。
- 正确字母不证明选项内的命理公式正确。遇到“水泄火”“木生金”等错误，按基础生克纠正；若选择其职业等叙述，分开说明，不能将错误公式写入技能。取象词的“唯一”“更强”也不等于已经比较过其他候选。
- 常识或选项措辞提供的排除另行标明，不能计作命盘增益；解释相容、运行稳定与真实预测正确分开。公开题可能已被模型见过，新对话不等于排除了训练数据污染。

本技能交付的是可复用的算命方法。开发者的命例测试、评分和迭代工具位于发布仓库的 `maintainer/`，普通解读无须加载或运行。

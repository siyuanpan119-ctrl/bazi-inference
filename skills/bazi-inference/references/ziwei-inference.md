# 紫微斗数独立推演与双系统比较

本篇教 AI 用已经核验的紫微命盘回答具体问题，并与八字判断比较。一般用户仍只需提供出生时间、性别、出生地；资料规范化、分盘和比较由 AI 完成。这里的星宫解释属于传统推演，尚未证明加入本模块能提高具体事件命中率。

按需要阅读：[命盘与取法](#命盘与取法)、[本命分析](#本命分析)、[事项判断](#事项判断)、[大限与流年](#大限与流年)、[双系统比较](#双系统比较)、[回答方式](#回答方式)、[来源](#来源)。

## 命盘与取法

1. 先按 [calculation.md](calculation.md) 核验出生资料。紫微采用的农历月、五行局、大限不等于八字节气月、纳音取象或起运年龄，分别计算，不搬用另一系统的字段。
2. 用 `scripts/ziwei_chart.mjs` 取得实际星盘；调用参数读其 `--help`。它接收已规范的日期、时辰索引、性别和时间口径，不能替代出生地点、历史时区、夏令时核验。缺运行依赖时说明紫微计算未完成，继续可完成的八字分析，不手编星曜补盘。
3. `hour_index` 为早子 0、丑 1，依序到亥 11、晚子 12。原始钟表时间与已经指定的地支时辰分开保留；不能对后者擅自再扣夏令时。只有国家而不能确定城市时，参考城市只能作明确情景。
4. 保留输出中的 `engine`、完整 `profile`、`normalized_input`，解读 `natal` 与各个 `horoscopes`。`normalization.status=scenario` 的结果始终是情景盘；不能在正文中升级为确定出生盘。
5. 本适配器以固定的通行安星配置为起点，日界采用 `current`，晚子归当日；其他边界与四化、庙旺取表以实际 `profile` 为准。明确需要时另跑 `forward` 晚子次日分支，各盘独立重建十二宫、星曜与岁限，不把不同盘的有利部分拼接。
6. 区分农历新年与立春年界、农历月与节气月、虚岁与周岁，固定闰月处理和安星流派。出生接近这些边界时才作相关分支；不能为了让已知事件吻合而临时换派或换四化表。

`iztro` 支持 `default/zhongzhou` 安星规则及四化、亮度自定义。其配置具有全局状态，因此不同配置须隔离计算或完整重设。引擎版本固定只能保证取法可复现，不能证明解读准确。[配置说明](https://iztro.com/posts/config-n-plugin)。

## 本命分析

先完成一份简短本命判断，再查看候选事件，避免先选故事再找星曜。保留命宫、身宫、所问主宫，以及它们真正改变判断的会照；不抄录全部杂曜。

### 先主星组合，再检查承接与牵制

- 从命宫主星及身宫说明做事倾向，再看官禄、财帛、迁移如何承接。身宫是补充观察面，不能自动取代命宫。
- 主星同宫按组合分析，不把每颗星的单独描述叠加成性格清单。庙旺陷度描述传统作用条件；庙旺不必然富贵，落陷也不等于行为恶劣。
- 左右、魁钺、昌曲可分别作为协助、机会、文书表达的线索；羊陀火铃、空劫等作为竞争、突发、消耗的候选条件。是否改变结论，要看它们落在哪里、与何主星及四化同组。
- 空宫先读对宫和三合宫的组合，同时保留本宫辅曜与四化关系；不能说没有主星就是没有婚姻、父母或事业。
- 单一星曜不负责决定职业、学历、疾病、性取向或品行。相同星系在不同宫位与时代条件下可以落实成不同生活方式。

以下只提供主星组合的起始观察方向，不能用来从十四颗星直接查出一个人生答案：

| 星曜方向 | 起始观察 | 必须继续区分 |
|---|---|---|
| 紫微、天府、天相 | 组织、资源管理、协调职责 | 是获授责任、协调岗位，还是实际控制经营资源 |
| 武曲、太阴 | 财务执行、积累、安排资源 | 是工资与回款、资产持有，还是资金负担 |
| 天机、巨门 | 规划、变通、分析与表达 | 是有效解决问题、职业表达，还是反复与争议 |
| 太阳、天梁 | 对外承担、服务、规则与支持 | 是得到认可、替人负担，还是职责失衡 |
| 天同、贪狼 | 体验、人际、欲望与适应 | 是社交助力、享受生活，还是分心消耗 |
| 廉贞、七杀、破军 | 边界、竞争、决断与变化 | 是建立秩序、重组发展，还是执行代价过高 |

### 三方四正与四化如何进入判断

以所问主宫为本宫，加两个三合宫及对宫一起读。例如命宫与财帛、官禄、迁移构成一组；夫妻宫另看福德、迁移、官禄。每次写清当前是哪一层的宫位，不能拿本命夫妻宫冒充流年夫妻宫。

用“主宫提出什么主题—会照提供什么支持—哪一项牵制使支持不能落实”形成短链。两颗星若只是重复同一方向，属于共有依据；一颗落在不同对象或不同时间层的星，才可能提供新信息。

四化依附于具体星曜，按以下方向提出候选解释，再核验整组条件：

| 四化 | 首先考察的变化 | 不能直接升级成 |
|---|---|---|
| 禄 | 增加、吸引、取得资源的渠道 | 净资产必增、中奖或固定金额 |
| 权 | 承担、掌控、执行及压力 | 必然升职、独占权力 |
| 科 | 可见度、名声、文书及支持 | 必然考取学历、获奖或无病 |
| 忌 | 牵挂、阻滞、耗损及难以处理的关系 | 必然破产、离婚、癌症或死亡 |

分别记录生年、大限、流年四化。每条至少说明“哪层天干→哪颗星→哪层主题宫→可能影响”。同星多层化象可以并存；不能相互抵消成一个吉凶总分，也不能将重复计算的同一关系计为多个证据。

宫干飞化另属明确的方法分支：保留发出宫、化星落宫和对宫，不与运限四化混写。没有事先固定的飞化解释规则时，先用本命、三方四正与岁限四化；不要临时加入自化、转宫来打破所有平局。

### 每个问题的完整最小底稿

不要只读摘要中的流年四化。对目标事项，由实际输出建立以下底稿；摘要未含的字段从原始 JSON 读取或补算，缺数据就标未完成，不凭星名记忆填盘。

| 层 | 必须保留 | 检查作用 |
|---|---|---|
| 本命 | 命身、目标宫及其两三合宫和对宫；各宫实际主星组合、相关辅煞、四化 | 定义稳定支持与瓶颈，分清本宫与会照 |
| 大限 | 实际区间、大限命宫、目标宫及三方四正；各宫叠到的本命宫；该限四化的来源干、化星与落宫 | 说明本命哪个条件在这个阶段被增强或削弱 |
| 流年 | 目标日期及年界；流年命宫、目标宫及三方四正；叠到本命和大限的位置；流年四化 | 说明相对大限常态真正新增的条件 |

落宫使用实际地支或索引作为稳定定位，再附该位置在各层的宫名。每项四化写成“来源层及干→化星→实际落宫→所涉阶段”；大限四化与流年四化都不能省略，生年四化不冒充大限四化。三方会照与四化若描述同一来源，只记一次支持，不按星曜或层数累加票数。

这套底稿完整仅表示取法可检查，不说明已辨认现实事件。每次至少给出一项可能使主判断撤回的牵制；主宫有吉象而三方承接受损时不能直接判成。

## 事项判断

按问题读取这一行及相关本命、岁限资料；不要求普通用户填写表格。对多项选择，将每个选项拆成事实子句，再比较哪些子句有区分依据。

| 所问事项 | 主要观察范围 | 得出结论的顺序 |
|---|---|---|
| 事业、职业 | 命、官禄、财帛、迁移 | 做事方式→资源取得与交易方式→岗位或经营形态→行业候选 |
| 财富、置业 | 财帛、田宅、官禄，福德辅助 | 收入/回款→成本与负债→留存及资产；买房与净赚分别判断 |
| 学习、考试、认可 | 命、官禄及昌曲魁钺、科的组合 | 学习条件→完成课程或考核→资格/名声；考试与就职分开 |
| 婚恋 | 夫妻及其三方四正，命、福德辅助 | 有无机会→关系建立→承诺登记→持续或终止，不由一次宫动包办全程 |
| 子女 | 子女宫与夫妻、田宅等相关安排 | 生育主题与家庭变化→时间窗口；性别、数量及生产方式另属难辨细节 |
| 父母、同胞 | 父母、兄弟及对应岁限宫 | 先明确对象，再比较关系、照顾、分离、资源；关系弱不等于人已死亡 |
| 个性 | 命身主星组合，福德、迁移辅助 | 内在偏好与外在应对分别说明，并给触发条件；避免道德定性 |
| 健康 | 本人疾厄、命身与相关岁限 | 仅讨论传统健康主题；本人、配偶或亲属的宫位变化不能随意互换 |

旁系亲属若要转宫，须提前说明采用的亲属关系与转宫路径，并检查原宫及岁限是否共同支持。若不同路径会指定不同对象，不能凭一次冲动或一颗煞曜锁定某位亲属。

职业的实用区分例：问“固定岗位还是经营”，官禄宫的组织、文书线索只说明工作形态；再看财帛如何承接交易、迁移如何取得外部资源。只有岗位支持而缺少经营承接时，先取受薪；两者兼有时，保留管理岗位与自营的竞争解释，不能因“有权”直接断老板。

婚恋的实用区分例：夫妻宫受动，若只有争执、牵挂或外部环境变化的线索，先解释互动增加或关系调整。要优先取登记，须另有建立承诺、生活安排落实的支持；要优先取离异，须已有婚姻事实或条件，且稳定承接受到实质削弱。自己的上一道猜测不是已知婚史。

## 大限与流年

### 由长期结构推进到具体年份

1. 先以本命解释所问主题的可发挥处和主要矛盾；不要仅看流年一宫就改变整个人生结论。
2. 加入目标大限，读大限命宫及所问宫位叠到本命哪一宫，四化改变了哪一组关系。紫微十年大限与八字大运可能起止不同，按各自计算结果处理。
3. 逐年比较流年对应宫、四化及与本命/大限的叠宫关系。先识别真正新增的条件，再检查是否延续原矛盾、补足承接，或损害现有支持。
4. 一年存在支持和阻碍时，问二者是否涉及同一对象与同一事件环节。文书认可与工资未增可以并存；购入房产与新增按揭也可以并存，不用总体“吉”吞掉代价。
5. 问一段多年经历，按大限分段并观察转折；问具体日期才细化流月。流月采用已固定的斗数边界，不把八字节气月名套在紫微月份上。

6. 问公历全年时覆盖所采用年界两侧和实际大限转换；全年代表日期仅是快照，不能把7月1日或其他单日结果称为整年。用户给具体日期则用该日期；只给月份且跨边界时保留前后段。各段采用同一事件卡，不以能吻合答案的那段代表整年。

### 比较候选年份时保持同一标准

对每年保留一句：**本命基础、当时大限、本年相对其他候选的新条件、最强反向条件。** 若四年都有同类夫妻宫变化，这个共有象不能决定哪年登记；须找到只在其中一年的承接区别，否则保持低支持排序。

优先顺序为：对象明确且贴合事件阶段的作用，优先于泛泛吉凶；跨本命与大限能解释的年度变化，优先于无背景的流年孤象；具体支持与反向条件经过比较的判断，优先于只列星曜数量。

这种优先顺序是本技能的推演约定，不是已估计的概率权重。不能把星曜组合多就称作更高准确率，更不能由“年份变化最大”推出极具体的伤亡方式、癌症器官或交易金额。

## 双系统比较

仅在两套命盘均已计算、各自边界清楚时进行融合。两套系统先各自完成 `event-discrimination.md` 的目标、结构、首选及最强备选。具备隔离执行能力时，两边获得相同原始资料和问题，各自不见对方排序及参考答案，完成后再合并；普通直接咨询不要求用户安排这个过程。

由同一个 AI 顺序完成时先保留第一套判断再开始第二套，不按第一套结论筛第二套星曜；但须承认同一上下文不能做到严格独立。两者共享出生资料、现实常识和可能的语义偏差，不是两次独立实证。答案已在上下文时，分离两套论证也不能恢复盲测状态。

实际留存八字、紫微各自的首选、备选、完整候选比较、前提和分支记录后，才生成合参结论。一个同时包含两列字母和共用理由的文件，只证明存在两列结果，不能证明两套原判断曾分别完成；不要把两列各自称为独立实测。采用 `decision-record.md` 的 `fusion` 引用指回原记录；检查器不替代宿主的上下文隔离。

先比较**同一对象、同一事件阶段、同一时间段**。若不同，先修正目标或拆成兼容的事件阶段；不能直接投票。八字财星、官杀、印不是紫微财帛宫、官禄宫或化科，紫微化忌也不是八字忌神。

| 比较结果 | 预先固定的处理 |
|---|---|
| 仅有“变化、财动、关系机会”等共有解释 | 共有背景不增加区分力；各自原判断同向则报告相容，原排序不同则仍保留分歧 |
| 一方新增只针对某候选的对象、阶段或时间条件 | 核验实际盘面、条件规则及来源层次，再检查另一方反证和现实前提；通过后才能提出融合首选，说明被改变的是哪个条件 |
| 新条件同时支持多个候选，或事件必需前提仍未知 | 不算独有区分；保留并列或有条件结论，不因另一方没有反证而自动优先 |
| 对同一事项有直接冲突 | 先核排盘边界，再核事件定义，最后核双方条件及反证；仍无法解决则列竞争答案并标分歧未解，不默认八字或紫微优先 |
| 其中一方的必要节点不存在或规则前提被实际数据否定 | 撤回该条论证，并说明是计算／前提错误；另一方仍按其自身区分力判断，不自动判其整项为事实 |
| 一套资料未确定或尚未计算 | 只交付已完成部分；分支差异影响哪些结论须注明，不写双盘印证 |

新增条件必须出自预先采用且可定位的原典／注释规则，或本文明确标记的操作假设。没有来源、条件、反证的临时联想不能调整排序；操作假设虽可试用，未经独立验证不得称为提升准确率的依据。排序依条件完整性，不设任意50/50权重、多数票、星曜计数或概率相乘。与用户明确事实冲突时，修正解释，不改写事实。

改票前把所谓新增条件改写成不含星名的现实差异，核对它是否仍同时容纳另一选项。例如“资源增加”没有区分工资、出售资产和意外收入；“出行”没有区分留学、工作和旅游。若仍共用，保留分歧。即使两系同选，仍分别查各子句的未知前提，不提高概率或确定性。强制答题可以保留一个未决首选，但任何默认保留策略只是交付约定，不代表八字或紫微更准。

宫干飞化、自化、延伸转宫如需试验，须在读候选前固定完整流派、起点、落点和解释规则，单独形成结果并保留基础分析；不能在基础分析平局后临时开启，也不能只挑其中吻合答案的部分合参。用户只要求一种系统时依其要求完成，不为凑双系统增加无关计算。

## 回答方式

直接问题先回答首选或主要趋势，然后说明最能改变结论的一两条依据和备选。年度报告按主题与阶段组织，只有双系统提供不同信息时才分别解释，不把所有宫位清单展示给用户。

可用句式：“主要倾向为〔判断〕。八字显示〔基础及岁运改变〕；紫微在〔目标宫、三方及岁限〕增加了〔具体区分条件〕，所以在〔前提〕下更偏向〔事件阶段〕。若〔关键前提〕不成立，较接近〔备选〕。”没有新增区分条件时只报告共有主题；原排序不同则说明分歧，不为凑首选默认选择任何一套。

涉及疾病、死亡、犯罪、性取向、彩票及精确财富等细节，传统类象相容不能当作已识别事实。遵守 `question-analysis.md` 第九节：无法鉴别的病种、死亡或犯罪等选项保持无法鉴别，不能借紫微补猜。其余可以比较的传统主题仍直接回答；精确金额等未知细节不得补成事实。

- [iztro 快速开始](https://iztro.com/quick-start)、[宫位接口](https://iztro.com/posts/palace)、[运限接口](https://iztro.com/posts/horoscope)：查实际宫位、星曜、层级和返回结构；软件提供计算，不自动证明事件解释。
- [作者四化说明及默认十干表](https://iztro.com/learn/mutagen)、[配置与插件](https://iztro.com/posts/config-n-plugin)：区分默认取法与可配置分支；当代作者的解释不冒称为统一古法。
- [固定发行版 v2.6.1](https://github.com/SylarLong/iztro/releases/tag/v2.6.1)、[MIT 许可证](https://github.com/SylarLong/iztro/blob/main/LICENSE)：核对计算依赖及保留许可。
- [香港天文台公农历对照表](https://www.hko.gov.hk/tc/gts/time/conversion1_text.htm)：独立核对农历日期和闰月，不用命理网站彼此转述替代历法依据。

以上来源支持传统取法与软件能力，不支持“融合已提高准确率”的结论。命理师间意见一致与对应真实人生事实是不同问题，不能由前者直接推出后者。

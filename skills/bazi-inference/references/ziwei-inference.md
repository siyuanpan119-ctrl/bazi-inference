# 紫微斗数独立推演与双系统比较

本篇教 AI 用已经核验的紫微命盘回答具体问题，并与八字判断比较。一般用户仍只需提供出生时间、性别、出生地；资料规范化、分盘和比较由 AI 完成。这里的星宫解释属于传统推演，尚未证明加入本模块能提高具体事件命中率。

按需要阅读：[命盘与取法](#命盘与取法)、[本命分析](#本命分析)、[事项判断](#事项判断)、[大限与流年](#大限与流年)、[双系统比较](#双系统比较)、[回答方式](#回答方式)、[来源](#来源)。

## 命盘与取法

1. 先按 [calculation.md](calculation.md) 核验出生资料。紫微采用的农历月、五行局、大限不等于八字节气月、纳音取象或起运年龄，分别计算，不搬用另一系统的字段。
2. 用 `scripts/ziwei_chart.mjs` 取得实际星盘；调用参数读其 `--help`。它接收已规范的日期、时辰索引、性别和时间口径，不能替代出生地点、历史时区、夏令时核验。缺运行依赖时说明紫微计算未完成，继续可完成的八字分析，不手编星曜补盘。
3. `hour_index` 为早子 0、丑 1，依序到亥 11、晚子 12。原始钟表时间与已经指定的地支时辰分开保留；不能对后者擅自再扣夏令时。只有国家而不能确定城市时，参考城市只能作明确情景。
4. 保留输出中的 `engine`、完整 `profile`、`normalized_input`，解读 `natal` 与各个 `horoscopes`。`normalization.status=scenario` 的结果始终是情景盘；不能在正文中升级为确定出生盘。
5. 本适配器以固定的通行安星配置为起点，日界采用 `current`，晚子归当日；其他边界与四化、庙旺取表以实际 `profile` 为准。明确需要时另跑 `forward` 晚子次日分支，各盘独立重建十二宫、星曜与岁限，不把不同盘的有利部分拼接。
6. 区分农历新年与立春年界、农历月与节气月、虚岁与周岁，固定闰月处理和安星流派。出生接近这些边界时才作相关分支；不能为了让已知事件吻合而临时换派或换四化表。

`iztro` 支持 `default/zhongzhou` 安星规则及四化、亮度自定义。其配置具有全局状态，因此不同配置须隔离计算或完整重设。引擎版本固定只能保证取法可复现，不能证明解读准确。[配置说明](https://iztro.com/posts/config-n-plugin)。

## 本命分析

先完成一份简短本命判断，再推进具体事项，避免先定故事再找星曜。用户已给职业、关系进程或过去事件时据此固定所问对象与真正未知变量；已知事实不算新增预测。保留命宫、身宫、所问主宫，以及它们真正改变判断的会照；不抄录全部杂曜。

### 先主星组合，再检查承接与牵制

- 从命宫主星及身宫说明做事倾向，再看官禄、财帛、迁移如何承接。身宫是补充观察面，不能自动取代命宫。
- 主星同宫按组合分析，不把每颗星的单独描述叠加成性格清单。庙旺陷度描述传统作用条件；庙旺不必然富贵，落陷也不等于行为恶劣。
- 左右、魁钺、昌曲可分别作为协助、机会、文书表达的线索；羊陀火铃、空劫等作为竞争、突发、消耗的候选条件。是否改变结论，要看它们落在哪里、与何主星及四化同组。
- 空宫先读对宫和三合宫的组合，同时保留本宫辅曜与四化关系；不能说没有主星就是没有婚姻、父母或事业。
- 单一星曜不负责决定职业、学历、疾病、性取向或品行。相同星系在不同宫位与时代条件下可以落实成不同生活方式。

以下只提供主星组合的起始观察方向，不能用来从十四颗星直接查出一个人生答案：

| 星曜方向 | 起始观察 | 必须继续区分 |
|---|---|---|
| 紫微、天府、天相 | 组织、资源管理、协调职责 | 是获授责任、协调岗位，还是实际控制经营资源 |
| 武曲、太阴 | 财务执行、积累、安排资源 | 是工资与回款、资产持有，还是资金负担 |
| 天机、巨门 | 规划、变通、分析与表达 | 是有效解决问题、职业表达，还是反复与争议 |
| 太阳、天梁 | 对外承担、服务、规则与支持 | 是得到认可、替人负担，还是职责失衡 |
| 天同、贪狼 | 体验、人际、欲望与适应 | 是社交助力、享受生活，还是分心消耗 |
| 廉贞、七杀、破军 | 边界、竞争、决断与变化 | 是建立秩序、重组发展，还是执行代价过高 |

### 三方四正与四化如何进入判断

以所问主宫为本宫，加两个三合宫及对宫一起读。例如命宫与财帛、官禄、迁移构成一组；夫妻宫另看福德、迁移、官禄。每次写清当前是哪一层的宫位，不能拿本命夫妻宫冒充流年夫妻宫。

用“主宫涉及哪个实际环节—会照的支持如何到达—牵制破坏了什么、哪些支持仍可用”形成短链。忌、煞不能直接代表终局，禄、科也不能一律降为不改变结果的救应。两颗星若只是重复同一作用，只算共有依据；不同宫层是否增加信息，仍看实际对象和作用是否不同。

四化依附于具体星曜，按以下方向提出候选解释，再核验整组条件：

| 四化 | 首先考察的变化 | 不能直接升级成 |
|---|---|---|
| 禄 | 增加、吸引、取得资源的渠道 | 净资产必增、中奖或固定金额 |
| 权 | 承担、掌控、执行及压力 | 必然升职、独占权力 |
| 科 | 可见度、名声、文书及支持 | 必然考取学历、获奖或无病 |
| 忌 | 牵挂、阻滞、耗损及难以处理的关系 | 必然破产、离婚、癌症或死亡 |

分别记录生年、大限、流年四化。每条至少说明“哪层天干→哪颗星→哪层主题宫→可能影响”。同星多层化象可以并存；不能相互抵消成一个吉凶总分，也不能将重复计算的同一关系计为多个证据。

宫干飞化另属明确的方法分支：保留发出宫、化星落宫和对宫，不与运限四化混写。没有事先固定的飞化解释规则时，先用本命、三方四正与岁限四化；不要临时加入自化、转宫来打破所有平局。

### 每个问题的完整最小底稿

按问题读取适用层：只问原局个性或基本发展方式时，可停在本命；涉及某运、某年时再加入相应大限和流年。不要只读摘要中的流年四化；适用层由实际输出建立以下底稿，摘要未含的字段从原始 JSON 读取或补算，缺数据就标未完成，不凭星名记忆填盘。

| 层 | 必须保留 | 检查作用 |
|---|---|---|
| 本命 | 命身、目标宫及其两三合宫和对宫；各宫实际主星组合、相关辅煞、四化 | 定义稳定支持与瓶颈，分清本宫与会照 |
| 大限 | 实际区间、大限命宫、目标宫及三方四正；各宫叠到的本命宫；该限四化的来源干、化星与落宫 | 说明本命哪个条件在这个阶段被增强或削弱 |
| 流年 | 目标日期及年界；流年命宫、目标宫及三方四正；叠到本命和大限的位置；流年四化 | 说明相对大限常态真正新增的条件 |

落宫使用实际地支或索引作为稳定定位，再附该位置在各层的宫名。每项四化写成“来源层及干→化星→实际落宫→所涉阶段”；涉及具体流年时，大限四化与流年四化都不能省略，生年四化不冒充大限四化。三方会照与四化若描述同一来源，只记一次支持，不按星曜或层数累加票数。

这套底稿完整仅表示取法可检查，不说明已辨认现实事件。围绕主判断比较最强竞争解释：同一环节的支持是否仍能发挥、牵制是否真正截断承接；把尚存的支持说明为可用条件，再判断它能否推动所问阶段实际落实。工作资源不等于当下在职，关系支持不等于婚姻仍存，田宅安排不等于拥有产权；反过来也不能有忌便把可用的支持抹掉。

## 事项判断

按问题读取这一行及相关本命、岁限资料；不要求普通用户填写表格。先锁定真正未知的方向、阶段或时间；将收入渠道、承接和最终留存分别判断，不因附带细节未知就放弃已有方向。

| 所问事项 | 主要观察范围 | 得出结论的顺序 |
|---|---|---|
| 事业、职业 | 命、官禄、财帛、迁移 | 做事方式→资源取得与交易方式→岗位或经营形态→行业候选 |
| 财富、置业 | 财帛、田宅、官禄，福德辅助 | 收入/回款→成本与负债→留存及资产；买房与净赚分别判断 |
| 学习、考试、认可 | 命、官禄及昌曲魁钺、科的组合 | 学习条件→完成课程或考核→资格/名声；考试与就职分开 |
| 婚恋 | 夫妻及其三方四正，命、福德辅助 | 有无机会→关系建立→承诺登记→持续或终止，不由一次宫动包办全程 |
| 子女 | 子女宫与夫妻、田宅等相关安排 | 生育主题与家庭变化→时间窗口；性别、数量及生产方式另属难辨细节 |
| 父母、同胞 | 父母、兄弟及对应岁限宫 | 先明确对象，再比较关系、照顾、分离、资源；关系弱不等于人已死亡 |
| 个性 | 命身主星组合，福德、迁移辅助 | 内在偏好与外在应对分别说明，并给触发条件；避免道德定性 |
| 已给健康经历的回看 | 本人疾厄、命身与相关岁限 | 已给病史作条件，聚焦时间或生活安排；主题不能充当临床诊断，本人、配偶及亲属宫位不互换 |

旁系亲属若要转宫，须提前说明采用的亲属关系与转宫路径，并检查原宫及岁限是否共同支持。若不同路径会指定不同对象，不能凭一次冲动或一颗煞曜锁定某位亲属。

职业先拆成工作内容、组织形式和收入路径：教学、照护、设计、销售等内容，与受薪、管理、自营等形式分别比较，再看工资、服务收费、交易回款怎样承接。官禄的组织线索不能独占解释为行政岗，财帛的资源线索也不能独占解释为金融业；各行业均用同样的区别标准，不给首选宽泛相容、却要求竞争项有专属星曜。岗位与经营支持兼有时，保留任职兼营的可能，不能强行二选一。用户已给出国、创业或收入来源时，直接据此缩小范围，不再将迁移、田宅等共有背景算作识别行业的新依据。

婚恋的实用区分例：夫妻宫受动，若只有争执、牵挂或外部环境变化的线索，先解释互动增加或关系调整。要优先取登记，比较承诺与生活安排能否落实；要优先取离异，明确婚姻是已知事实还是待判前提，再比较稳定承接是否实质削弱。自己的上一条推断不是已知婚史；若竞争解释都需先有婚姻或新伴侣，对它们采用同一标准，不能只以某一身份缺专属依据来排斥它。

## 大限与流年

### 由长期结构推进到具体年份

1. 先以本命解释所问主题的可发挥处和主要矛盾；不要仅看流年一宫就改变整个人生结论。
2. 加入目标大限，读大限命宫及所问宫位叠到本命哪一宫，四化改变了哪一组关系。紫微十年大限与八字大运可能起止不同，按各自计算结果处理。
3. 逐年比较流年对应宫、四化及叠宫关系，以本命和大限常态为基线。原有组合重现、同一作用增强、出现新承接分别解释；重现可以支持原作用延续或增强，但须说明本年多改变了哪一环，不能仅因再见便认定本年首次落实某事。
4. 支持和阻碍须落实到同一对象、同一环节后比较。若都作用于经营周转，检查资金或交付路径是否仍可运行，不将阻碍直接判倒闭、支持仅称救应；若作用不同，分别给结果，如认可增加而工资未增、购房同时新增按揭。主次取决于承接是否可用，不按吉煞数量抵消。
5. 问一段多年经历，以各段大限结构说明持续作用，再用相关流年定位转折和持续时长；末段一两年的好坏只支持该段变化，不能代表整个十年。问具体日期才细化流月，采用已固定的斗数边界，不把八字节气月名套在紫微月份上。

6. 问公历全年时覆盖所采用年界两侧和实际大限转换；全年代表日期仅是快照，不能把7月1日或其他单日结果称为整年。用户给具体日期则用该日期；只给月份且跨边界时保留前后段。各段采用同一事项和判断口径，不以能吻合反馈的那段代表整年。

### 比较年份时保持同一标准

对每年保留一句：**本命基础、当时大限、本年相对其他年份的新条件、最强反向条件。** 若多年都有同类夫妻宫变化，共有象只能支持关系阶段；应比较其中承接、稳定性和现实进程的区别，再给优先年份。没有足够差异时保留阶段窗口，不人为制造某年独有的应期。

优先顺序为：对象明确且贴合事件阶段的作用，优先于泛泛吉凶；跨本命与大限能解释的年度变化，优先于无背景的流年孤象；具体支持与反向条件经过比较的判断，优先于只列星曜数量。

这种优先顺序是本技能的推演约定，不是已估计的概率权重。不能把星曜组合多就称作更高准确率，更不能由“年份变化最大”推出极具体的伤亡方式、癌症器官或交易金额。

## 双系统比较

补算是否能解决当前缺口，按主入口和 `event-discrimination.md` 判断；普通简单咨询不必一律双盘。仅在两套命盘均已计算、各自边界清楚时合参。两套系统先各自完成对象、结构、主判断、反向条件和时间分支；普通咨询用简短文字或表格底稿即可，不强制逐项 JSON、字母排序、`fusion` 字段或检查器。

具备隔离执行能力且分析规模值得时，两边获得相同出生资料、已知背景和问题，各自不见对方结论后再合并；普通用户无须安排这个过程。由同一个 AI 顺序完成时先保留第一套判断，再按第二套完整取法分析，不按已有结论筛星。顺序分析不称严格独立；两者共享出生资料、现实常识和语义偏差，也不是两次独立实证。

合参先对齐**同一对象、同一事件阶段、同一实际时间段**。八字财星、官杀、印不是紫微财帛宫、官禄宫或化科，紫微化忌也不是八字忌神。若一方判断岗位责任、一方判断现金留存，应保留两个可并存结论，不能先归为总体吉凶再相互抵消。

两份底稿至少各自保留：实际命盘与边界、所问作用链、主要判断及最强竞争解释、能改变判断的条件。不要在已经合并的结论后补写两列相同理由并声称独立完成。合参比较的是解释对目标的贴合及条件是否成立，不预设八字或紫微优先。

| 比较结果 | 如何形成用户结论 |
|---|---|
| 两边只有“变化、资源活跃、关系机会”等共有方向 | 报告方向相容；共有背景不解决具体阶段与结果，也不增加一次独立命中 |
| 一方增加明确对象、事件环节或时间窗口条件 | 写明新增条件使哪个候选的哪一环更成立、另一候选为何较弱；核验盘面、规则及反向作用后才收窄。定位对象更直接不自动证明具体终局更可靠 |
| 两方分别支持来源改善与承接代价 | 按来源、承接、结果分别组织，如交易更活跃但回款负担上升；不能用总体“吉”吞掉代价 |
| 同一对象、阶段与时间出现直接冲突 | 先查排盘边界、事项定义、遗漏的会照与救应；仍有分歧时说明暂采用哪条主线及理由，保留会使其改判的条件 |
| 某方必要节点不存在，或前提被实际数据否定 | 撤回该条论证，同步重审原判断与新判断的排序；只凭该条建立的优势一并撤回，另一方仍按自身依据判断 |
| 一套资料不确定或尚未计算 | 完成可用系统并注明范围；不虚构另一系统，也不称双盘印证 |

对新增条件，说明其来自既定原典／注释框架或明确标记的技能操作假设；没有出处与成立条件的临时联想不能用于压倒另一判断。未经新命例验证的操作假设，不称为已提高准确率的方法。宫干飞化、自化、延伸转宫须在使用前固定完整取法，不能在基本判断难分后只加入吻合某一结果的部分。

改判保留一条短链：**新增或纠正的材料→受影响的子项→相对最接近竞争表现的区别→仍未知的部分**。回读原底稿，已经用过的支持不能再次算新增；只增加学习支持不能提高学历层次，只增加家庭安排不能直接锁定出生年份。用不含星名的现实含义作替换检查：若同样支持两边，仍是共有主题，不能取得唯一领先。

撤销旧理由只取消旧优势，提出新判断仍须自己的区别；两方均查支持与反向，按 `event-discrimination.md` 比较同一领域和阶段。定位主体更直接、解释更长或后加入的体系都不自动优先。两系统同向不按星曜数量、任意权重、多数票或概率相乘提高把握。

完整补查后若仍并列，保留未决范围。必须单选时固定一次选择及真实状态；已有完整比较后的提交，且没有新材料或可定位错误时，不因再次总结而重选。保留字母只为防止无依据的重复选择，不表示先选者更可信，也不让无依据首选阻止实际纠错。有新区别时同步修订主判断、最近竞争项与相关日期分支，不把改口本身称为合参收益。

用户只要求一种系统时按其要求完成，不为凑双系统增加无关计算。用户明确要求命例选项比较、评分或结构化审查时，另读 `exercise-mode.md`，对应的记录协议不强制用于日常合参。

## 回答方式

直接问题先给主判断，再说明最能改变结论的一两条依据和必要条件。年度报告按主题与阶段组织，双系统提供不同信息时才分别解释；不将全部宫位清单展示给用户。

可用句式：“这段时间更倾向……，主要限制是……。八字主线是……；紫微补充了……，因此将重点放在……。如果……，则应改看……。”没有新增区别时说明两套解释相容即可，不需要为了合参而追加更精确的人生故事。

把方向、应期和具体细节分开表达：可以明确优先岗位责任扩大、资源周转活跃或关系安排落实，同时保留职级、金额或登记日期的条件。缺少未给传记不是所有方向无区别的理由；解释相容也不能写成已核实的人生事实。

现实诊断、治疗、法律或投资行动，以及个人敏感属性、寿限等请求按 `question-analysis.md` 第九节和适用上位要求处理。两系统均不能把未知事实变成已知，也不能通过合参将文化解释升级为专业证据。

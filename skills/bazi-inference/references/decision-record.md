# 结构化审计记录（按需）

本页仅供用户明确要求结构化审计或机器评测时读取。成组题、版本比较及合参默认保留 `exercise-mode.md` 所述的简短原始记录；普通咨询不建立逐题 JSON。新结构化记录采用现有 v3，旧记录保持原样读取。

先完成实际推演，再保存相应依据；工具不代替判断，也不要求用户填写数据或提供答案。合法、已提交的记录并不证明排序有支持；不得用批量模板、空引用或补造 `supported` 状态取得完成标记。本页保留 v3 检查标准，不能以默认记录简化为由降低显式审计要求。

## 从问题写到记录

合成格式见 `assets/decision-record.example.json`。每个问题一份JSON；八字、紫微分别保存，合参记录引用两份原件。字段只服务实际判断，不为凑齐而补造未知事实。

| 字段 | 填什么 |
|---|---|
| `schema_version` | 新记录用整数`3`；兼容旧版`1`、`2`，不得只改版本号冒充已完成新检查 |
| `target` | `subject`主体、`event_stage`事项阶段、`time_scope`实际时间范围；v3另列非空且不重复的`facets`，固定本题真正要区分的维度 |
| `candidates` | 全部候选，每项的`id`和`claims`；复合叙述拆成最小子事实 |
| `claims[].state` | `known`用户明确给定；`supported`传统解释相容；`unknown`未确定；`contradicted`与已核验事实或声明结构冲突 |
| `claims[].evidence_ids` | 对应实际依据；不能拿“未知”当已不存在 |
| `evidence` | 每项含`id`、`kind`、`scope`、`source_ref`、`statement` |
| `evidence[].kind` | `calculation`可复算事实；`user_fact`已提供生平；`traditional_interpretation`从符号到事件的解释假设 |
| `evidence[].scope` | `background`多个候选共有；`discriminator`声明有区别，但还须人工审查它是否确实区分 |
| `evidence[].status` | 可选，默认`available`（有这条声明，不代表已验证）；明确未知标`unknown`，只缺正面支持标`missing_support`。后两者不能作为支持、反证或区分依据 |
| `primary`、`strongest_alternative` | 本轮首选及主要对照；不是已知事实。字段名为兼容保留，并列时对照不代表已比其他并列项更强。普通选择题仍填首选 |
| `ranking` | v3全候选排序，二维ID数组，每项只出现一次；从优先到次选，同一内层数组表示并列，如`[["A","C"],["B"]]` |
| `ranking_reason` | v3非空说明：各层为何先后、共有背景与真正差异、最强反向条件；无法区分就说明并列，不能事后补理由 |
| `selection_basis` | v3用`relative_support`或`guess`；表示本轮选择依据，不能把相对支持当完整事实确定或概率 |
| `comparison` | 首选摘要：`against`列所有其余候选；`discriminator_ids`、`why_distinguishes`、`counterevidence`及`required_unknowns`分别列区分、反向与未满足前提。仅列ID不算实际逐项比较 |
| `candidate_reviews` | 每个候选一条同标准审查，字段见下表；包含保留的基线首选和弱备选 |
| `decision_mode` | `conditional`有条件判断；普通答题中难以区分但仍交付首选时为`forced_choice`，无需用户另外说“强制” |
| `temporal_branches` | 实际分析过的分支`id`及其`primary`，可选`note`记录日期/时辰说明；v3各分支另有完整`ranking`、非空`ranking_reason`，多分支各列`basis_evidence_ids`指向自身的可用计算依据 |
| `expected_temporal_branch_ids` | 计算层发现会影响本题的完整分支清单；用于检查有没有漏掉某段 |
| `fusion` | 两系统各自的`primary`和`record_ref`，另列`override_reason`与`discriminator_ids`；有冲突时无论改票或保留基线都要说明区别，不能只要求挑战者举证 |

这里的`known`只表示用户提供了该事实，不表示已外部核验；`supported`须对应实际支持的子句，仍不表示事件发生或已胜过对照。仅支持“关系有摩擦”时，不给“已婚且被配偶责骂”整句标支持；不能为接上引用而把未知子句升级为支持。`calculation`只写可复算的盘面和区间，喜忌、六亲映射及事件解释另列；引用指向真实文件与可定位字段，不拼接不存在的字段路径。

子句对回原文的主语、量词、否定范围与截止时间。例：“创业、拥有数套房、净资产达某金额”有三个不同主张，不能用经营主题支持全部；未知金额也不能反向证明较小金额成立。已知事件只问应期时，不重新要求证明事件、地点或人物背景；这些背景也不为某候选独享。

`claims[].text`写选项本身的事实主张；“没证据”“可能相容”“无法排除”等评语放入审查字段，不用评语替换题面。`target.facets`从真实差异生成，例如“考试资格”“入职”或“收入趋势”“债务责任人”；混合事项不能全部压成“具体选项事实”。字段描述真实完成的分析，不是批量填空后获得完成标记的模板。

### 每候选同样审查，不能只给首选写理由

`candidate_reviews`每条使用以下字段，`id`对应一个候选。有同类候选时先审其中最强竞争解释，再看其他候选，避免只排除异类就选定具体财务或关系事件。支持和反向由逐项分析产生，不能按主选分配引用；比较文字承认备选有支持时，结构记录也要保留。数组为空只表示实际审过仍暂无，不强迫弱备选编造证据。

| 字段 | 填什么 |
|---|---|
| `support_ids`、`counterevidence_ids` | 分开列支持与反证ID；各自覆盖该候选`known/supported`、`contradicted`子事实所引依据。支持须连接本候选，反证也可列独立的反向条件 |
| `required_unknowns` | 按原`claims[].text`列全该候选的`unknown`子事实，可补其他必要未知；不能漏掉、改成反证或从另一系统借答案 |
| `strongest_alternative` | 对这个候选最强的另一个解释；首选条目须与顶层同名字段一致 |
| `discriminator_ids` | 本次比较声明的区分依据，须连接本候选或所比较备选的支持/反证。无法区分可为空，不要求每个候选都胜出 |
| `comparison` | 简短写该候选与其最强备选各能解释什么、区别及局限；可明确较弱或无法区分，不能只写已比较的ID |
| `facet_reviews` | v3逐一覆盖`target.facets`，每维度恰好一次；格式见下段，与该候选自身的事实和证据连接 |

每条`facet_reviews`为`{"facet":"目标维度原文","state":"unknown","evidence_ids":[]}`。`state`有四种：`relative_support`声明有相对支持；`shared_background`只有共有背景；`unknown`暂无区别；`counterevidence`有反向条件。相对支持须引用可用且连接该候选支持/反证的`discriminator`；不得拿共享的学习、工作或财务主题证明完成学历、具体行业或收益量级。独立反向结构可以放在该候选的`counterevidence_ids`并被维度引用，不要求把仍未知的选项事实改成`contradicted`；未知本身仍不能当反证。未知可留空引用，不强制创造差异。程序核对维度覆盖与显式引用，不验证这些对应在自然语言或现实中是否成立。

例如“是否入学未知”属于未知；“未找到毕业支持”属于缺正证，都不是“没有毕业”的反证。若将这种缺口列成依据，必须用`status`如实标记；脚本会阻止其进入支持、反证和区分清单，也会阻止同一候选把未知子事实的引用同时当反证。不同子事实的相反作用须分开写依据。不写这些状态而把未知藏在自然语言中，程序无法可靠识别，仍须人工核对。首选必要条件未知时，证据保持未决，但仍可交付标明猜测的首选；不要为使检查结果好看而删除未知条件。

`effective_status=unresolved`不要求把`ranking`改成全项并列：具体事实未证实与条件上的相对排序是两个判断。确有连接候选与目标维度的区分依据时，可以保留`selection_basis=relative_support`和原排序，同时保留未知子句；正文说明“有相对倾向，具体细节未定”。只有共有背景或未找到实际差异时，才采用并列和`guess`。示例文件展示了相对支持与修读事实未知同时存在的记录。

## 从一份排序生成选择与比较

先固定目标维度，再独立写各候选审查，最后形成`ranking`。首选须在最高层；去掉首选后，最强备选取剩余最高层中的一个。每个候选的主要对照同样来自排除自身后的最高层；首选审查的最强备选与顶层字段保持一致。并列组内的数组顺序不代表强弱；从并列中选一个交卷时标`guess`，不声称该字母已胜出。全部都未知时可写`[["A","B","C","D"]]`，仍保留非空首选。

新增或撤回理由后重审排序，同步首选、备选、比较文字与最终答卷，并保留改判前记录。人工旁注须与结构记录表达同一判断；不能仅替换字母或向全部候选追加同一句“最终说明”。`ranking_reason` 说明区别覆盖的维度；为 `guess` 时说明是仅有相容线索还是全无区分依据。检查器能发现部分结构冲突，最强同类竞争是否真正审过、旧理由是否仍支持当前排序，仍须人工核对。

对影响本题的时间分支，v3同时提供`expected_temporal_branch_ids`和各分支完整排序及理由。分支明确并列时可保留`primary=null`，其含义是已比较但没有唯一首选；缺少排序或理由则表示比较没有记录完整。两者不能混为一谈，也不能以同一个`-natal`标签替代实际跨节或交运区段。最终总排序说明分支差异怎样影响选择，不凭任意分支权重折算概率。

多分支的`basis_evidence_ids`连接本记录中`kind=calculation`、可用且带本分支`source_ref`的依据。例如两个换日盘分别引用各自的`chart.pillars`及相关岁运段；同一报告的两段用不同字段路径。分支专属ID但共用同一来源不算独立计算引用。引用齐备后，理由仍需解释该盘改变了什么、为何排序改变或未变；程序不读取来源真实性，也不验证独立解释已经完成。旧v3漏此可选字段仍可读和交卷，但多分支声明需补审。

## 检查并回到实际判断

```bash
python scripts/decision_record.py --input /absolute/path/judgment.json --output /absolute/path/judgment-check.json --markdown /absolute/path/judgment-summary.md
```

`--markdown`可省略；摘要标题由同一记录字段生成，正文不自动改写，不修复错误推理。三个文件使用不同路径，禁止覆盖原始记录。格式错误先修正。结果为未决时，查看缺的是哪条区别；有必要且可取得的资料就补，没有则保留证据未决并交付最终首选。普通答题默认需要作答，不额外要求用户授权猜测。`effective_status=unresolved`与`primary`有字母可以并存；这表示答案已经提交而证据仍有限，不是检查器禁止作答。不能为了升级状态编造支持，也不能删掉困难选项或把备用项算作答对。

检查输出的 `submission_status` 单独描述交付：`submitted` 表示有效记录已有首选，`missing_choice` 表示尚未填写，`invalid_record` 表示先修正格式。它不表示答案正确、适宜对现实个人作事实判断或获得额外行动授权。完整题卷在交付前核对题号总数和每题首选，`effective_status` 未决不应让已提交答案消失。

交卷之外，读取这些复核字段，不能只看程序成功退出：

| 输出 | 如何使用 |
|---|---|
| `primary_ranking_status` | `relative_basis_declared`仅表示首选唯一领先且有连接的相对依据声明；`tied`表示首层并列；`unsupported`或`inconsistent`要求回查排序；旧版为`not_checked` |
| `alternative_role` | `ranked_alternative`为按声明排序选出的备选，`tied_comparator`仅为并列对照，`unverified_alternative`为待核对照；摘要使用对应称谓 |
| `review_completion_status` | `declared_complete`只表示声明记录齐备，不能证明实质推断完成；`needs_review`表示可定位的补审缺口，旧版为`not_checked` |
| `review_actions` | 按提示补读计算、修正对象或核对依据连接；按 `event-discrimination.md` 完成相关补查后，无法取得的事实保留未知，继续交单一首选 |

检查提示分两类处理：**未完成工作**，如漏算分支、漏审最强同类竞争、旁注有依据但引用未连接，须完成实际工作并修正记录；**真实未决**，如已比较仍只有共用主题、需要不可取得的生平事实，保留未知及猜测。不能把字段合法当作比较完成，也不能把每个警告都当成必须产生区别的要求。

`empty_candidate_basis` 提示支持、反向引用均空且维度全未知；整批集中出现时回查 `event-discrimination.md` 的共用主线、目标拆分和实际阅读。真实全未知仍可提交，模板化空记录不算审查。若旁注声称已有相对优势而 JSON 仍全未知，先解决二者的判断或引用缺口，不能只用旁注宣称已完成。

v2/v3漏全部或部分候选审查会降为未决；v3的`review_standard=target_facets_v3`，还检查目标维度、排序与分支。v1不带`candidate_reviews`仍按旧规则读取，结果标`review_standard=legacy_v1`；v2仍标`symmetric`，不会冒称完成v3审查。字段类型损坏或ID无效先修正，不由检查器补选候选。漏记维度、排名不完整、首选/备选错位等声明缺口记录在`issues`中，证据未决仍保留最终字母。

v3的`temporal_review_statuses`逐分支报告`incomplete`（排名或理由未齐）、`needs_review`（多分支缺专属计算引用）、`compared_tie`（比较声明齐备、首层并列）、`compared`（比较声明齐备、首层单项）。这些都只说明声明情况，仍须结合`issues`检查选择是否一致，不表示分支推断正确。多分支复用相同理由又缺专属计算引用时，`copied_temporal_comparison`提示回看实际分盘；改ID或改写同一句话不能完成补审。

`quality_warnings`与证据问题分别返回。多个候选完全重复的非空比较，或只换前缀而大段结尾相同，会提示人工复核；检查器只检测文字复用，不判断其语义真假。先检查是否已分别审查目标维度、是否只是引用了共同背景；不要为了消除提示同义改写或编造不同理由。诚实的全未知仍可交卷，短小的共有说明未必需要重复警告。没有提示也不证明比较有效，错误事件对应或前后语义矛盾仍需人工发现。

程序只验证声明的字段、引用关系、候选和分支覆盖，不核实古籍、外部文件内容、自然语言真实性或现实预测效度。把“财动”错误地写成`discriminator`仍可能通过；必须人工再问：它是否也支持另一候选？若是，改为共有背景。`relative_basis_declared`只表示声明的结构检查通过，不是医学诊断、法律事实、事件发生或“高准确率”。

同理，保存两个`record_ref`不证明宿主真正隔离过上下文。独立执行应先形成原记录，后交给合参步骤；同一上下文顺序完成时如实说明。`fusion.agreement_as_confidence`若为真，表示错误地以同票提升确定性，应撤回这项提升。

这些约定维护的是记录与实际判断的一致性，不证明事件预测命中率提高。具体推演沿用 `event-discrimination.md`；日常输出先回答问题，再说明少量关键依据，完整 JSON 和维护评测流程只在用户所要求的审计任务中交付。
